# Working rules (agreed in Slice 38h, rewritten in Slice 44a)

1. **Roles.** The owner decides the questions and the design. The agent writes code, tests and docs **and runs the checks itself**: `uv run ruff format .`, `uv run ruff check .`, `uv run mypy apps`, `docker compose exec web python manage.py makemigrations <each app the prompt names>`, `docker compose exec web python manage.py makemigrations --check --dry-run` and the full `docker compose exec web python -m pytest -q`, and it also runs the deliberate breakages with `python tools\review.py mutate tools\mutations\mutations-NN.json`. It fixes what fails and pastes the raw output in its report. The agent still never touches `.env`, never runs git except the read-only `git status --short`, never writes a migration by hand, and edits settings or `pyproject.toml` only when the prompt names them. Claude directs: asks the due questions, writes the prompts, reads the pulled diff, writes the mutation list and reads the review report. Claude does not run pytest or PostgreSQL in its own sandbox.
2. **Questions first.** Before each slice Claude lists the open questions that are due in `docs/open_questions.md` and the design choices of the slice, each with a default. The owner answers "all defaults" or changes some. Only then the prompt is written.
3. **Big prompts.** One slice is one prompt, two at most when it truly cannot fit. No a/b/c/d splitting. The agent does all the work and we check at the end. A prompt names its slice, lists the files to read first, states the goal and the fixed decisions, starts with a short PLAN step followed at once by the work, has numbered work items with the docs last, lists the exact names of the tests with a minimum count, has a "Do not" list and a final-message format, and ends with STOP. Prompts give goals, fixed decisions and exact test names, not finished code (exceptions: exact doc text and tiny exact patches).
4. **After the agent stops** (owner, Windows Command Prompt, repo folder): read the report and the check output it pasted; when the report says a migration is pending (or names one the agent wrote), run `docker compose exec web python manage.py migrate`; then `git status --short`, `git add -A`, `git commit -m "Slice N: ..."`, `git push`; finally delete the prompt file (`del slice-N-prompt.md`; `slice-*-prompt.md` is listed in `.git/info/exclude`). The owner does not repeat the checks the agent already ran unless the report says one could not run.
5. **Review.** The helper `review.py` lives in `tools/` inside the repo, and the agent runs the breakages itself with `python tools\review.py mutate tools\mutations\mutations-NN.json` (`python tools\review.py checks` and `... suite 3` when the prompt asks for them) and reports the `mutations:` line of each run. Claude writes `mutations-NN.json` (each target text must match exactly once) and reads the report the run appends. Never run the review while the agent is working: the script edits files in place.
6. **Survivors** are sorted into test gaps (a carry-over test in the next slice's prompt, not a separate tiny slice), equivalent mutants (explain and ignore) and tool artifacts (`--reuse-db` hides edits to model constraints).
7. **A slice is done** when the checks pass, the test count rose by at least the promised number, the full suite passes three times, the breakages are caught or the survivors explained, the docs are updated (decisions, STATUS, open questions, Python recap) and the prompt file is deleted.
8. **Mark** anything about money, stock, security or login as REVIEW CAREFULLY.
