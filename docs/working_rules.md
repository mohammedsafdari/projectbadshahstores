# Working rules (agreed in Slice 38h)

1. **Roles.** The owner runs everything that executes. The OpenCode agent writes code, tests and docs and never runs a command (no pytest, ruff, mypy, makemigrations or git), never touches `.env`, never writes a migration, and edits settings or `pyproject.toml` only when the prompt names them. Claude directs: asks the due questions, writes the prompts, reads the pulled diff, writes the mutation list and reads the review report. Claude does not run pytest or PostgreSQL in its own sandbox.
2. **Questions first.** Before each slice Claude lists the open questions that are due in `docs/open_questions.md` and the design choices of the slice, each with a default. The owner answers "all defaults" or changes some. Only then the prompt is written.
3. **Big prompts.** One slice is one prompt, two at most when it truly cannot fit. No a/b/c/d splitting. The agent does all the work and we check at the end. A prompt names its slice, lists the files to read first, states the goal and the fixed decisions, starts with a short PLAN step followed at once by the work, has numbered work items with the docs last, lists the exact names of the tests with a minimum count, has a "Do not" list and a final-message format, and ends with STOP. Prompts give goals, fixed decisions and exact test names, not finished code (exceptions: exact doc text and tiny exact patches).
4. **After the agent stops** (owner, Windows Command Prompt, repo folder): `docker compose exec web python manage.py makemigrations <app>` only when the prompt says a migration is pending; then `uv run ruff format .`, `uv run ruff check .`, `uv run mypy apps`, `docker compose exec web python -m pytest -q`, `git status --short`, `git add -A`, `git commit -m "Slice N: ..."`, `git push`; finally delete the prompt file (`del slice-N-prompt.md`; `slice-*-prompt.md` is listed in `.git/info/exclude`).
5. **Review.** The helper `review.py` lives in `C:\dev\badshah-tools` (outside the repo). The owner runs `python C:\dev\badshah-tools\review.py checks`, `... suite 3` and `... mutate C:\dev\badshah-tools\mutations-NN.json`, and pastes the lines after the last `==` header. Claude runs `git pull`, checks with `git log` that the push has arrived, reads the diff (design, security, money, login), writes `mutations-NN.json` (each target text must match exactly once; Claude validates it against the pulled repo) and reads the report. Never run the review while the agent is working: the script edits files in place.
6. **Survivors** are sorted into test gaps (a carry-over test in the next slice's prompt, not a separate tiny slice), equivalent mutants (explain and ignore) and tool artifacts (`--reuse-db` hides edits to model constraints).
7. **A slice is done** when the checks pass, the test count rose by at least the promised number, the full suite passes three times, the breakages are caught or the survivors explained, the docs are updated (decisions, STATUS, open questions, Python recap) and the prompt file is deleted.
8. **Mark** anything about money, stock, security or login as REVIEW CAREFULLY.
